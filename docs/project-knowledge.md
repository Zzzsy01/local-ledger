# 项目经验

- 参考排版是 A4 竖版（595.32 × 841.92 pt），左右边距 90 pt，上下边距 72 pt。发票在上，淘宝和支付截图在下并排；普通图片尺寸略有差异，允许不超过 5% 的等比例缩小，明显较长的发票另页。
- 淘宝商品行的“实付价”是单价，订单行的“实付款”才是本工具采用的金额；付款行内可能夹有“共减 ¥3”等优惠说明，应定位行右侧金额。
- 微信支付账单可能写“淘宝平台商户”，仅有“淘宝”字样不能判为淘宝订单。订单信息、收货信息与账单字段组合才有区分意义。
- 整页中文 OCR 会把某些大号金额数字读错，不能靠正则猜字或用支付账单替代淘宝金额。复用整页 OCR 的行坐标定位金额，再以英文数字模式读取小区域；仍不明确则让用户核对。
- 浏览器离线缓存只包含代码和模型。静态程序资源不随 Origin 变化；匹配缓存时忽略服务器的 `Vary: Origin`，避免模块请求与预缓存请求的头部差异造成空响应。
- 当前票据状态只由 `application/receipt-service.js` 管理。界面提交操作并渲染显示快照，不能直接改角色、金额或触发能力层；界面与 WebMCP 共用服务入口。业务记录与图片资源分开保存，预览和 PDF 使用服务层同一次计算的排版。扩展位置和依赖方向见 README，静态导入边界由小型测试检查。

上述经验属于本工具及其票据来源，不提升为整个 finance 的通用开发约束。
