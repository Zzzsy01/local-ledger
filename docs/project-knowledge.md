# 项目经验

- 参考排版是 A4 竖版（595.32 × 841.92 pt），左右边距 90 pt，上下边距 72 pt。发票在上，淘宝和支付截图在下并排；普通图片尺寸略有差异，允许不超过 5% 的等比例缩小，明显较长的发票另页。
- 淘宝商品行的“实付价”是单价，订单行的“实付款”才是本工具采用的金额；付款行内可能夹有“共减 ¥3”等优惠说明，应定位行右侧金额。
- 微信支付账单可能写“淘宝平台商户”，仅有“淘宝”字样不能判为淘宝订单。订单信息、收货信息与账单字段组合才有区分意义。
- 整页中文 OCR 会把某些大号金额数字读错，不能靠正则猜字或用支付账单替代淘宝金额。复用整页 OCR 的行坐标定位金额，再以英文数字模式读取小区域；仍不明确则让用户核对。
- 浏览器离线缓存只包含代码和模型。静态程序资源不随 Origin 变化；匹配缓存时忽略服务器的 `Vary: Origin`，避免模块请求与预缓存请求的头部差异造成空响应。
- 当前票据状态只由 `application/receipt-service.js` 管理。界面提交操作并渲染显示快照，不能直接改角色、金额或触发能力层；界面与 WebMCP 共用服务入口。业务记录与图片资源分开保存，预览和 PDF 使用服务层同一次计算的排版。扩展位置和依赖方向见 README，静态导入边界由小型测试检查。

上述经验属于本工具及其票据来源，不提升为整个 finance 的通用开发约束。

## 安卓记账

- 原生工程位于 `android`，网页票据逻辑仍在原 `src`，两者暂不共享运行时代码。安卓 UI/ViewModel 只调用 Repository；Room Entity 不暴露给 UI。`domain` 放纯 Kotlin 模型与规则，`data/db` 负责持久化与映射，`data/backup` 负责 JSON 和文件 IO，四个页面按功能分包；具体边界见 `android/ARCHITECTURE.md`。
- 停用分类／账户不能从历史 JOIN 或统计中排除；只过滤流水自身的 `isDeleted`。编辑历史可保留原停用关联，新流水不能选停用项。
- SQLite `SUM` 会在多个合法 Long 金额的总和超限时抛出 `integer overflow`。在保存事务和备份恢复校验中分别约束收入、支出的活动总额；不要用 REAL/Double 掩盖金额溢出。
- 本地备份采用事务读取完整账本后导出 JSON，再校验并事务恢复；当前版本 3 包含三张记账表、物品、备忘录、预算和固定规则共七表。不要直接复制运行中的 SQLite 主文件而遗漏 WAL。Android 原生 JSON 对整数使用 Int/Long；备份校验不能用会强制转换字符串或浮点数的 `getLong`。
- Room schema 提交至 `android/app/schemas`；后续版本必须提供保留数据的迁移路径，禁止破坏性重建数据库。
- 物品二手估值独立于收支和支付账户，不自动产生收入／支出。用户提供的挂牌报价均值必须标明来源性质，不能表示为平台成交均价。
- APK 覆盖更新要求同包名、同签名和递增版本号；更新源的 SHA-256 只能检查下载完整性，客户端还必须校验实际 APK 包名、版本与已安装签名。备份不包含更新源设置。
- 固定账目的本期确认与下期推进必须共用数据库事务并检查原到期日，防止重复确认；每月 29—31 日要保留原目标日，短月临时用月末。分类被固定规则引用后不能改收支类型。
- CSV 导入先解析和预览再一次事务写入；导入标识随软删除和完整备份保留。无稳定来源 ID 时，原文件哈希只能防同文件重选，不代表跨文件可靠去重。
- 记账和备忘录是同级主页；默认主页决定新会话入口，正在运行的导航不随设置变更而重建。切换使用 Navigation 的保存／恢复状态，底部主页返回当前模式。
- 报表日期区间包含结束当天，数据库查询仍使用当地日历的半开毫秒边界。按日聚合使用本地日期，不能按固定 24 小时分桶；长区间按月汇总时仍先限制真实日期边界。日期与周期配置一次更新，避免自定义起止日期分开发出时出现中间无效区间。
- 更改 `ANDROID_USER_HOME` 会更换默认调试密钥位置。已有 APK 覆盖安装前应核对签名并使用原密钥，不能通过卸载应用处理签名不一致。
- GitHub 更新清单使用 `releases/latest/download/update.json` 固定地址，清单内 APK 必须指向具体版本标签，避免发布新版期间出现清单与安装包不一致。安装包先作为草稿附件全部上传，再将 Release 发布为最新版；源码提交与 Release 标签保持对应。
- Android 安装来源权限变更可能杀死应用进程，更新下载状态不能只依赖 ViewModel。重新读取当前清单后，可复用经哈希、包名、版本和签名再次验证的缓存 APK；不能仅凭文件存在就允许安装。
